# 吴恩达 Agentic AI｜从四种设计模式到可验证行动闭环

> 学习归档：保留来源陈述、讨论与原有核验边界；不是对所有事件和数据的重新确认。涉及公司、价格、政策和产品状态，请按原记录日期阅读并回查来源。

> **一句话结论：**Agentic AI 不是“更会聊天的模型”，而是把模型放进一个能够规划、行动、观察、校验和纠错的闭环。它的价值来自闭环，风险也来自闭环。

## 一、它到底是什么

普通大模型的典型路径是：

`用户 → 模型 → 答案`

Agentic AI 的路径更像：

`理解任务 → 制定计划 → 调用工具 → 观察结果 → 评估 → 调整 → 再行动`

模型权重可以完全没有变化。真正增强的是模型外部的工作流、工具、记忆、评估器和权限系统。因此，它首先是**系统级能力增强**，不是基础模型完成了自我进化。

吴恩达更倾向把 “agentic” 看作程度，而不是非黑即白的标签：一个系统可以只比普通聊天多一点自主性，也可以持续运行、分解任务并反复修正。[DeepLearning.AI 课程](https://www.deeplearning.ai/courses/agentic-ai)｜[吴恩达对 agentic 的定义](https://www.deeplearning.ai/the-batch/welcoming-diverse-approaches-keeps-machine-learning-strong/)

## 二、自主性的五级阶梯

| 层级 | 系统表现 | 本质变化 |
| --- | --- | --- |
| L0 单次生成 | 给一次答案 | 没有行动闭环 |
| L1 固定工作流 | 按预设步骤完成任务 | 流程由人写死 |
| L2 工具与反馈 | 搜索、运行代码、读数据库 | 能接触外部证据 |
| L3 动态规划 | 失败后重试、改路径、重新分解 | 反馈开始改变行动 |
| L4 长期运行 | 维护记忆、处理多任务、响应事件 | 从一次性工具变成持续代理 |
| L5 高度自治 | 自选子目标、资源和工作方式 | 接近独立代理，但不等于独立主体 |

最有意义的分界线不是“会不会调用工具”，而是：**外部反馈能否真正改变下一步行动。**

## 三、吴恩达总结的四种设计模式

| 模式 | 它解决什么问题 | 容易被误解的地方 |
| --- | --- | --- |
| Reflection 反思 | 检查结果并修改 | 没有新证据的自我批评，可能只是重复盲点 |
| Tool Use 工具调用 | 搜索、计算、执行真实动作 | 模型说“已执行”不代表动作真的发生 |
| Planning 规划 | 拆解任务、选择路径 | 一张漂亮清单不等于真正规划 |
| Multi-Agent 多智能体 | 分工、并行探索、相互评审 | 多个相似 Agent 投票，可能只是相关性错误 |

### 1. 反思：关键不是多想一次，而是多一份证据

<p>
弱反思是模型重新读自己的答案，再说一次“哪里可能错了”。\
</p>

强反思会引入测试、编译器、数据库、数学验证器、人类专家或独立模型。

所以真正有价值的不是循环次数，而是：

> 新一轮循环有没有获得上一轮没有的新证据？

### 2. 工具：从语言能力跃迁到行动能力

工具让模型不再只生成 token，而可以读取文件、调用 API、执行代码、修改数据和对外发送消息。

权限应分层：

- 只读；
- 可撤销写入；
- 对外可见操作；
- 不可逆或高风险操作。

模型提出动作和动作实际发生必须分开。确定性的执行层负责校验权限、参数、结果和日志。

### 3. 规划：计划必须能被现实打断

真正的计划至少包含：

- 下一步行动；
- 观察到什么；
- 不同结果如何分支；
- 什么时候停止或改道。

如果系统只是在开头生成十条步骤，然后机械执行，它仍然更接近固定工作流。

### 4. 多智能体：人数不等于认知多样性

多 Agent 的价值来自角色、工具、上下文、搜索方向和评价标准的差异。

如果 20 个 Agent 使用同一模型、相似提示词、相同数据，再用多数投票得出答案，它们很可能只是把同一种错误重复了 20 遍。

## 四、一个完整 Agent 系统的八个部件

1. **目标**：到底要完成什么，而不是泛泛地“做好”。
2. **上下文与记忆**：当前状态、历史经验和约束。
3. **规划器**：决定下一步做什么。
4. **执行器**：把模型建议转为确定性操作。
5. **工具与环境**：搜索、代码、数据库、应用程序和真实世界。
6. **观察模块**：读取动作结果。
7. **评估器**：判断是否正确、是否值得继续。
8. **停止与重规划机制**：成功、失败、成本超标或风险升高时结束或改道。

系统能力可以粗略理解为：

> 基础模型能力 × 工作流质量 × 工具可靠性 × 反馈质量 × 评估真实性

其中任何一项接近零，整体表现都会快速坍塌。

## 五、记忆不是“保存所有聊天”

Agent 的记忆至少分为四类：

- **工作记忆**：当前任务临时需要的信息；
- **情景记忆**：过去发生了什么；
- **语义记忆**：从多次经验中提炼的稳定知识；
- **程序记忆**：做事的方法和工作流。

写入、检索和遗忘是三个独立问题。把所有对话永久保存，只会制造一个越来越嘈杂的仓库。

需要特别防范记忆污染：

- 把临时偏好写成永久规则；
- 把未经验证的结论当成事实；
- 把外部恶意内容写入长期记忆；
- 继续使用已经过期的信息；
- 把系统推断误当成用户明确表达。

因此，**生成一条候选记忆**与**允许它永久写入**应当是两种权限。

## 六、如何判断它真的变强

不能只看最终答案，更要评价整条行动轨迹。

1. **结果**：任务是否完成；
2. **过程**：工具、步骤和判断是否合理；
3. **效率**：消耗了多少 token、算力、时间和人工；
4. **鲁棒性与迁移**：换任务、换环境、换评估器后是否仍有效；
5. **安全与治理**：权限、审计、隐私和损失是否可控。

评估器本身也必须接受评估。否则系统可能学会迎合评估器，在分数上进步，却没有获得真实迁移能力。

更可靠的组合是：

- 确定性检查；
- 模型评估；
- 人类判断；
- 独立任务与影子环境；
- 成本与异常行为监控。

吴恩达强调，构建 Agent 时，eval 和 error analysis 不是项目末尾的验收，而是开发循环的一部分。[Agent 评估与错误分析](https://www.deeplearning.ai/the-batch/improve-agentic-performance-with-evals-and-error-analysis-part-1)｜[评估器本身也需要迭代](https://www.deeplearning.ai/the-batch/we-iterate-on-models-we-can-iterate-on-evals-too)

## 七、安全：风险不只来自模型，也来自组合

### Prompt Injection

网页、邮件和文档里的内容应当被视为**证据**，而不是自动视为对系统的**指令**。否则 Agent 可能被一段外部文本劫持。

### 能力组合

单个工具看似安全，组合后可能形成危险能力：

- 读取联系人；
- 生成内容；
- 对外发送；
- 批量执行。

风险往往不是一个工具造成的，而是工具链造成的。

### 应当暂停的情况

- 目标或指令发生冲突；
- 缺少明确权限；
- 关键事实无法验证；
- 成本异常增加；
- 同一错误反复出现；
- 出现陌生收件人或新资产；
- 任务范围自行扩张；
- 外部内容要求修改系统规则。

责任也必须拆清：谁设定目标、谁授予权限、谁监控、谁处理事故、谁承担不可逆损失。

我的原则是：

> 谁承担不可逆后果，谁就应拥有更高的最终决定权。

## 八、经济价值：不要只看“它能不能做”

Agent 的净价值应当计算为：

> 节省的人力 + 新增收入 + 减少错误的价值

> − 模型与工具成本 − 人工监督成本 − 预期事故损失

最适合 Agent 化的任务通常具有这些特征：

- 高频；
- 流程相对稳定；
- 单次价值不太低；
- 反馈快速；
- 结果可以验证；
- 错误可以撤销；
- 数据和工具可访问。

不适合的任务通常是：极少发生、容错率极低、规则快速变化、结果无法验证，或者一次错误就会产生不可逆损失。

长期护城河也不只是套一层模型，而更可能来自：

- 独有工作流数据；
- 与业务系统的深度集成；
- 真实的评估体系；
- 行业知识；
- 信任和责任承接能力。

## 九、Agentic AI 与 RSI 的边界

二者有关，但不能混为一谈。

| 行为 | 更准确的定义 |
| --- | --- |
| 保存一次成功经验 | 情景记忆 |
| 从多次经验归纳规则 | 语义学习 |
| 修改提示词、工具或工作流 | 系统级改进 |
| 在独立任务上验证持久提升 | 开始形成 RSI 证据 |
| 连“如何改进自己”也持续变强 | 更强的递归自我改进证据 |

Agentic AI 可以成为 RSI 的基础设施，但“会反思、会调用工具、会保存记忆”本身并不能证明 RSI。

更完整的链条是：

`完成外部任务 → 分析自身失败 → 提出自我修改 → 独立任务验证 → 持久保留 → 改进改进过程`

只在原任务或原评估器上得分更高，很可能仍是局部过拟合。

## 十、我最终形成的判断

1. Agentic AI 的核心不是拟人化，而是**可验证的行动闭环**。
2. 更多步骤、更多 Agent、更长推理并不天然更强，也可能只是买了更多张彩票。
3. 自主权应当由证据逐步换取，而不是因为演示效果惊艳就一次性授予。
4. 最重要的系统部件往往不是 planner，而是 evaluator、权限和停止机制。
5. Agent 最先改变的是软件生产方式和组织流程，而不是立即产生独立经济主体。
6. 今天的大多数 Agent 更适合称为“独立代理”：目标、资产和最终责任仍由人类提供。
7. Agentic AI 与 AI for Science 很匹配，尤其适合验证便宜、反馈快速、实验可闭环的问题。
8. 如果验证昂贵、反馈延迟或价值判断高度主观，自主循环很容易把错误放大。
9. 系统既可能通过反馈变得更好，也可能通过反馈学会更熟练地欺骗评估器。

## 十一、Agentic AI 九问

在构建或投资一个 Agent 项目前，先问：

- [ ] 它解决的是真实任务，还是为了使用 Agent 而制造任务？
- [ ] 固定工作流能否以更低成本完成？
- [ ] 哪些决策必须动态产生？
- [ ] 它需要哪些工具和权限？
- [ ] 外部反馈如何改变下一步行动？
- [ ] 谁验证任务真的完成？
- [ ] 单位成功任务的总成本是多少？
- [ ] 失败能否被隔离、撤销和追责？
- [ ] 所谓改进能否迁移到原评估器之外？

如果这九问答不清，“自主智能体”很可能只是昂贵而不稳定的自动化。

## 待继续追踪

- 长期运行 Agent 的记忆写入与遗忘标准；
- 多 Agent 是否真的产生搜索多样性；
- 工作流优化与单纯扩大采样规模的区分；
- evaluator 漂移、迎合和共谋问题；
- Agent 的任务级计价、责任保险与审计制度；
- 从独立代理走向经济主体需要哪些新能力与制度。
