# 具身智能数据：从“数据量”竞争到“有效交互闭环”竞争

> 学习归档：保留来源陈述、讨论与原有核验边界；不是对所有事件和数据的重新确认。涉及公司、价格、政策和产品状态，请按原记录日期阅读并回查来源。

机器人数据究竟缺什么？哪条路线能形成可持续的数据飞轮？

## 工作性结论

具身智能的关键约束并非“缺少画面”，而是缺少能把**感知—动作—接触结果—失败恢复**连成闭环的训练样本。企业的竞争单元应从“数据条数”改为：

> 单位成本下，持续制造难例、验证模型收益、并从真实部署回流的速度。

## 判断框架

| 维度 | 应问的问题 |
| --- | --- |
| 真实性 | 是否有力觉/触觉、控制量、失败及恢复，还是只有成功视频？ |
| 可迁移性 | 跨物体、跨场景、跨本体后是否仍提升，还是只记住了某套遥操轨迹？ |
| 经济性 | 每个有效小时的全成本、合格率与训练收益是否可量化？ |
| 闭环性 | 线上部署如何发现难例、合规采集、筛选、再训练与回归测试？ |
| 可验证性 | 有没有独立 benchmark、任务成功率、恢复率、长时稳定性与对照实验？ |

## 四层数据的正确分工

- **真机遥操**：用在接触、控制和失败恢复的“真值”上；
- **仿真合成**：用在覆盖长尾、扩场景和训练前筛选上；
- **动捕**：用在动作先验与人类任务结构上；
- **互联网视频**：用在语义、物体和场景覆盖上。

任何单层都难以独立解决问题；关键在于按目标任务设计数据配方，并用真机评测决定下一轮采集什么。

## 后续跟踪信号

- 公开 benchmark 是否开始评估恢复、长时任务和跨环境泛化，而非单次成功；
- 数采平台是否披露可复现的数据协议、质检标准和成本/有效小时；
- 仿真数据进入真机任务后带来的增益是否可独立复现；
- 商业部署是否形成“异常 → 回流 → 更新 → 复测”的稳定节奏。
