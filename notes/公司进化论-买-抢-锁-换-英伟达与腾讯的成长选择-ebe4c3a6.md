# 《公司进化论》｜买—抢—锁—换：英伟达与腾讯的成长选择

> 学习归档：保留来源陈述、讨论与原有核验边界；不是对所有事件和数据的重新确认。涉及公司、价格、政策和产品状态，请按原记录日期阅读并回查来源。

> **一句话收获**：这四本书不是四套孤立理论，而是一条公司进化链：先让主流客户敢买，再在窗口期抢到默认位置，把价值锁进难以替代的控制点，并在旧控制点变成标配前迁往下一代 Core。

## 1. 四本书压缩成「买—抢—锁—换」

| 动作 | 对应著作 | 真正要回答的问题 | 正确动作 |
| --- | --- | --- | --- |
| 买 | 《跨越鸿沟》 | 主流客户为什么敢买？ | 补齐完整产品，承担集成、交付与责任边界。 |
| 抢 | 《龙卷风暴》 | 市场爆发时该抢什么？ | 从验证需求切换到标准、供给、渠道和默认位置。 |
| 锁 | 《猩猩游戏》 | 谁控制架构并捕获利润？ | 占据标准、接口、工作流、生态与迁移成本。 |
| 换 | 《公司进化论》 | 旧优势变成标配后，资源去哪里？ | 让 Context 更便宜可靠，把资源迁往下一代 Core。 |

<p>
**Core** 是会改变客户购买选择、形成溢价和迁移成本的能力。  
</p>

<p>
**Context** 是同样关键、不能出错，却不再构成客户选择理由的能力。  
</p>

重要不等于 Core；不能出错也不等于客户愿意付溢价。

## 2. 英伟达：显卡 → 开发工作流 → 集群系统 → AI 工厂

| 时间与选择 | 用四书理解 | 战略含义 |
| --- | --- | --- |
| 1999：游戏 GPU | 建立品类、开发者和现金流基础。 | 游戏 GPU 是 AI 曲线的工程与经济前史，不应与 AI 市场混成一条线。 |
| 2006：CUDA | 早期用户的通用并行计算平台；提前埋下工作流控制点。 | 不满足于卖更快显卡，把竞争单位从硬件扩到开发环境。 |
| 2012：深度学习验证 | 早期市场出现强证据，不等于已经跨鸿沟。 | 论文突破必须被翻译成客户可部署、可负责的完整产品。 |
| 2016：DGX | 「买」：从零部件转向完整产品。 | 把 GPU、软件、框架、支持和管理打包，替客户承担集成风险。 |
| 2020：Mellanox | 「锁」：把互连纳入控制点。 | 竞争单位上移为集群、网络、软件和工程协同，而不只是单卡。 |
| 2022–2023：生成式 AI 爆发 | 「抢」：供给、交付、伙伴和工程默认路径同步扩张。 | 客户抢到的不只是卡，而是按计划训练、扩容和上线的确定性。 |
| 2024 至今：AI Factory | 「换」：尝试把下一代 Core 放到可靠运行与快速接入业务。 | 这是正在验证的进化，不是已完成的胜利。 |

### 我的英伟达判断

若有 100 元战略预算：

| 方向 | 预算 | 判断 |
| --- | --- | --- |
| AI 工厂系统与开发者生态 | 50% | 争夺下一代 Core：稳定运行、快速部署、工程工作流和平台依赖。 |
| 芯片 | 30% | 守住性能地基；没有硬件领先，系统层缺少可信底座。 |
| 供给 | 10% | 极其重要，但更可能是阶段性 Core，供需恢复后会回归 Context。 |
| 企业软件 | 10% | 不应孤立成边缘业务，应嵌入 AI 工厂，成为可靠性、治理和业务接入的控制层。 |

我认为企业最可能单独付费的结果是：

- **更少宕机**：可用性、调度、容灾、故障响应和 SLA；
- **更快把 AI 接进真实业务**：数据治理、权限、安全、部署工具、行业工作流与交付伙伴。

英伟达应采用的边界是：**核心自研，外围开放，伙伴交付，资本扶持。**

- 自研并控制：芯片—互连—系统软件协同、性能和可靠性控制面；
- 开放：接口、认证、参考架构、行业应用与交付能力；
- 让伙伴承担：云服务、咨询实施、行业流程、客户数据接入与本地化服务；
- 投资扶持：能扩大平台使用、强化接口依赖并增加高价值工作负载的公司。

生态投资只有在“伙伴每增长一元，平台更难替代、更多被使用或能卖出更多高价值能力”时才成立；否则只是渠道补贴，甚至可能资助出夺走客户关系的替代者。

### 英伟达的证伪条件

- 替代方案在大规模训练的总成本、稳定性和交付速度上同时追平，而非只在单卡跑分上接近；
- 框架、工具链和运维流程跨硬件标准化，客户常态化双供，不再需要重写、重测和重建团队流程；
- 云厂商与头部模型公司内化 AI 工厂控制面，只采购可比价部件；
- 企业不愿为可靠性与部署效率独立付费，AI Factory 只是更贵的机柜打包。

## 3. 腾讯：聊天 → 关系图谱 → 身份与支付 → 服务生态

| 时间与选择 | 用四书理解 | 战略含义 |
| --- | --- | --- |
| 1999–2010：QQ | 建立 PC 时代的关系网络、账号体系与规模化运营能力。 | 旧曲线很成功，但不能因此把 PC 社交当作永久 Core。 |
| 2011–2012：微信 | 「换 + 买」：主动开出移动原生新曲线，再跨移动互联网的采用鸿沟。 | 不把 QQ 简单搬到手机，而以通讯、语音、朋友圈和公众号重构日常连接。 |
| 2013–2014：支付与红包 | 「抢」：抢交易习惯、账户信任和支付网络。 | 把绑卡、转账和支付嵌入社交仪式，而不只是增加结账功能。 |
| 2014：京东合作 | Core / Context 分工。 | 不自营库存、物流和全链路电商；腾讯守住关系、入口、支付与连接能力。 |
| 2017：小程序 | 「锁」：把身份、关系、传播、支付和运行规则做成平台控制面。 | 商家、开发者和公共服务负责具体业务与履约。 |
| 2018 至今：产业互联网、内容与企业连接 | 「换」：聊天界面逐步标配化后，继续探索服务连接、内容、交易和企业能力。 | 关系、身份、信任和平台规则仍是 Core；新业务必须重新跨鸿沟，不能借微信规模假定成功。 |

腾讯的经验可以压成一句：

> 腾讯守住“城市的入口、身份证、交通规则与支付网络”，让伙伴去开店、送货和完成具体服务。

## 4. 相同结构，不同控制面

| 维度 | 英伟达 | 腾讯／微信 |
| --- | --- | --- |
| 跨鸿沟时补齐什么 | 训练、部署、运维、SLA 与责任边界 | 联系人迁移、日常沟通、交易信任 |
| 龙卷风时抢什么 | 供给、系统交付、工程默认路径 | 关系密度、支付习惯、服务入口 |
| 真正控制点 | CUDA、系统软件、互连、工程工作流 | 关系、身份、分发、支付与平台规则 |
| 向生态开放什么 | 云交付、模型、行业应用、咨询实施 | 商家服务、内容、垂类履约、小程序 |
| 最大风险 | 大客户和云厂商自研、双供，退回高端部件商 | 信任被透支、平台越界、伙伴变敌人 |

> **英伟达的护城河，是替换后工程会不会失控。**

> **微信的护城河，是替换后生活和关系会不会断链。**

微信是已被历史验证的“主动开出新 S 曲线”；AI Factory 是英伟达在 GPU Core 仍高度赚钱时，尝试上移竞争单位的一次巨大下注，仍需等待独立证据。

## 5. 迁移到个人第一性原理

以后分析公司，强制完成一张「公司进化地图」：

1. 具体业务／品类当前处于验证、爆发、成熟还是衰退？
2. 客户此刻真正为哪项结果付钱？
3. 当前 Core 是什么？哪些能力虽关键却已经是 Context？
4. 旧 Core 的商品化、替代或监管时钟是什么？
5. 下一代 Core 是什么？资源是否已经开始迁移？
6. 伙伴每成功一步，平台更强还是更弱？
7. 若判断错误，最大损失是什么？哪项证据触发减仓、转向或退出？

> **开放不是放弃控制。好的开放，是把 Context 放出去，让 Core 因生态而更强。**

>

> **不要等旧优势失效后才找新优势。最好的进化，发生在旧 Core 仍在赚钱时。**

## 6. 30 / 90 天观察单

### 英伟达

- 30 天：收集客户是否因可靠性、部署速度和运维能力而非单纯 GPU 采购的案例；观察替代方案是否进入关键任务和常态化双供。
- 90 天：判断系统可靠性、企业支持与部署效率能否形成独立的续费、复购或采购偏好；判断云厂商是否正内化控制面、把英伟达压回可比价部件。

### 腾讯

- 30 天：观察新服务是否强化关系、身份、支付与服务连接，而不只是制造内容时长。
- 90 天：判断生态伙伴增长是否更依赖腾讯的基础能力；旧 Core 是否 Context 化；新 S 曲线是否出现独立采用与价值捕获证据。
