# Token经济与Agent工程｜从OpenClaw、Hermes到多Agent与奇点证据

> 学习归档：保留来源陈述、讨论与原有核验边界；不是对所有事件和数据的重新确认。涉及公司、价格、政策和产品状态，请按原记录日期阅读并回查来源。

> **稳定结论：** Agent正在从“会调用工具”走向“会积累经验和组织计算”，但更多Token、更多Agent和更多Skill都不天然等于更强智能。只有在固定资源下产生可迁移、可证伪、经济上成立的真实增益，才算能力增长。

# 二、核心变化：从模型能力进入Agent工程

AI行业的关注点正在沿着这条路线迁移：

> 模型更聪明 → Agent长期工作 → 外部经验积累 → 多Agent组织计算 → 成本与收益治理 → 真实能力验证

OpenClaw的价值是把“模型＋工具调用＋循环执行＋本地优先”带给普通用户，验证了长期Agent的产品形态。它更像范式传播者，而非已经确定的最终赢家。

Hermes向前推进了一步：把成功任务整理成可复用Skill。它形成持久的外部经验积累，但没有修改基础模型权重，因此不能直接称为权重级学习或完整RSI。

Raft/Slock将多个Agent放入共享频道讨论。各Agent保留独立上下文，只共享频道信息，通过质疑、接续和代码审查扩大搜索深度。代价是Token可能增至单Agent的约十倍，且大量讨论可能重复。

# 三、Token Efficient的准确含义

Token Efficient不是少用Token，也不是一律选择便宜模型，而是：

> 在真实任务中，以更低的单位成本，稳定地产生可验证、可迁移的有效结果。

合理分工：

- 简单、明确、容易验证的任务交给本地或便宜模型。
- 高价值、高不确定任务交给前沿模型。
- 错误代价高、单模型容易遗漏时，启用多Agent审查。
- 用收入、成本节约、错误降低和真实部署衡量Token，而不是把Token消耗当KPI。

经济判断：

- 成本增加10倍、收益增加5倍：负优化。
- 成本增加10倍、收益增加10倍：线性扩张，单位效率没有提高。
- 成本增加10倍、风险调整后收益显著超过10倍：可能出现系统增益。

# 四、多Agent：搜索规模不等于协作智能

20个Agent产生更好的结果，可能只是买了20张彩票。应设置两组对照：

- **独立采样组B1：** 20个Agent各自尝试，最后选择最好答案。
- **协作组B2：** 相同Agent数量和Token预算，允许彼此质疑、修正与接续研究。

只有B2稳定优于B1，才能说明信息交换产生了额外价值。

需要继续通过：

1. **固定预算：** 协作优势不能仅靠增加Token获得。
2. **贡献链：** Agent甲的新证据改变Agent乙的路线，并形成初始答案中不存在的新结果。
3. **远距离迁移：** 优势从熟悉代码库迁移到陌生代码库、其他语言甚至非代码任务。
4. **经济效果：** 降低的风险或创造的收益超过新增算力、等待时间与系统复杂度。

阶段性判断：

> 当前多Agent更像昂贵的开放式搜索与交叉审查机制。未通过独立采样对照和远距离迁移前，不应称为更高层级的群体智能。

# 五、Skill积累：更隐蔽的过拟合

Skill让Agent执行更快、更规范，但可能把历史成功路径固化。它在相似任务上表现越来越好，面对关键约束变化时却可能迅速走错。

成熟Skill应包含：

**适用前提 → 分析方法 → 行动步骤 → 权限要求 → 证伪条件 → 退出机制**

约束变化时的处理原则：

- 保留可迁移的分析方法。
- 默认冻结删除、写入、授权等危险动作。
- 先用只读证据重新验证适用性。
- 只有获得新证据与明确授权后，才逐级恢复权限。

例如，旧Skill允许修改数据库，而新任务只能只读访问。正确做法不是直接复用，也不是全部抛弃，而是保留分析步骤、禁用写操作并重新验证。

> 真正的学习不是记住更多成功经验，而是知道什么时候怀疑、修改或放弃经验。

# 六、四种“学习”不能混为一谈

1. **上下文内适应：** 当前对话中使用新资料，清空上下文后能力基本消失。
2. **外部经验积累：** 记忆、代码、工作流和Skill持久更新；Hermes主要属于这一层。
3. **人类推动的模型更新：** 人类团队收集数据、设计训练并发布新模型，学习主体是整个人机研发体系。
4. **自主能力改进：** 系统自主发现缺陷、修改自身、设计实验、排除伪改进并部署新版本，才开始接近RSI。

节目关于“奇点已经到来”的证据主要来自模型版本迭代、IQ测试和编程能力。这些证据说明部分任务能力和人机研发体系进步很快，但不足以证明第四层已经成立。

# 七、判断自主改进的测量框架

至少测量五项：

- **未见任务增益：** 一轮改进后，在陌生任务上提升多少。
- **单位算力增益：** 能力提高相同幅度，需要多少GPU、Token、数据和人工。
- **远距离迁移：** 从代码优化迁移到陌生代码库、芯片设计、数学或其他领域。
- **人类依赖程度：** 谁定义问题、设计实验、验证结果、决定部署。
- **跨代递归增益：** 新一代是否比上一代更有效地改进下一代。

实验例：

| 代际 | 公开Benchmark增益 | 隐藏任务增益 | 算力 | 单位算力真实增益 |
| --- | --- | --- | --- | --- |
| 第一代 | 20% | 4% | 1 | 4% |
| 第二代 | 30% | 3% | 2 | 1.5% |
| 第三代 | 40% | 1% | 4 | 0.25% |

判断：系统具备自主修改能力，但主要在利用公开评估器；真实迁移增益递减，单位算力效率下降16倍。这不是智能爆炸，而是评估器利用速度超过真实学习速度。

# 八、对“奇点已经到来”的最终判断

目前可以确认：

- AI已经参与数据生成、编码、评估和部分系统改进。
- Agent能够积累外部经验、延长运行时间并扩大搜索。
- 部分认知和编程任务已经超过部分人类基线。

尚未充分证明：

- AI能自主发现自身根本缺陷。
- AI能设计不被自身利用的新评估。
- 多代改进能够远距离迁移。
- 单位算力研究效率跨代上升。
- 下一代能够比上一代更有效地改进再下一代。

因此更准确的结论是：

> 我们可能进入了AI参与改进AI的早期阶段，但尚无充分证据证明出现可泛化、单位算力效率持续提高的递归加速。

# 九、对产业与创业的判断

节目提出的企业级机会包括：

- 记忆与上下文管理。
- 多Agent协作。
- Agent运行环境、沙盒与Serverless基础设施。
- Token成本与收益追踪。
- 可观测性与人类干预接口。
- 面向Agent而非传统App设计的新型云服务。

其中可观测性最关键。企业真正需要知道：

- Token花在什么步骤。
- 哪个Agent贡献了关键证据。
- 哪些讨论只是重复。
- 人类应在哪一步介入。
- 错误发生后如何回溯与归责。

# 十、待继续跟踪

- 在固定Token预算下，多Agent能否稳定胜过独立采样。
- Skill系统能否识别错误Skill和相似但不适用的Skill。
- 多Agent协作优势能否跨代码库、跨语言、跨领域迁移。
- 本地模型＋前沿模型的路由是否真正降低单位任务成本。
- Agent可观测性产品能否把“讨论很多”转化为可审计的贡献链。
- 隐藏评估本身如何避免被长期运行的系统反向学习。
