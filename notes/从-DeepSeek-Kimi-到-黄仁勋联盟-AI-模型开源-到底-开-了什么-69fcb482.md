# 从 DeepSeek、Kimi 到“黄仁勋联盟”：AI 模型开源，到底“开”了什么？

> [观看原视频](https://www.youtube.com/watch?v=NEHcGq80GQ0)

## 核心问题

“开源模型”常被当成一个标签，但真正需要问的是：**它究竟开放了什么，以及你因此获得了什么权利与能力？**

## 三个层次

| 形态 | 通常开放什么 | 使用者能做什么 | 仍然看不到/受限什么 |
| --- | --- | --- | --- |
| **闭源模型** | API 或产品界面 | 调用能力、快速集成 | 权重、训练过程、内部数据与完整评测 |
| **开放权重** | 可下载的模型参数，常附推理代码/技术报告 | 本地部署、私有数据推理、一定程度的微调与生态适配 | 训练数据、完整训练代码、真实训练过程通常不公开；许可证可能含使用限制 |
| **完全开源 AI** | 允许研究、使用、修改、再分发所需的模型、代码与数据来源信息 | 更接近独立审计、复现、修改和重建 | 实务上非常罕见；数据权利与算力门槛仍可能限制可复现性 |

## 访谈主线

### 1. 开源不是道德姿态，而是一种产业分工

模型公司把一部分能力交给外部开发者、云厂商、硬件厂商与行业客户，以换取：

- 更广泛的部署和分发；
- 更多兼容性、推理优化与工具链贡献；
- 对闭源巨头的生态制衡；
- 让模型成为事实标准的机会。

因此，所谓“黄仁勋联盟”背后的经济逻辑并不神秘：只要更多模型在更多硬件、云和应用里运行，算力、推理服务和软硬件生态都有扩张空间。开放模型与闭源 API 并非互斥，而是服务不同市场。

### 2. 权重开放带来的是“可运行与可改造”，不是“可从零重建”

DeepSeek-V3 公开模型权重、推理相关材料和代码仓库，并允许商业使用，但其模型许可包含用途限制；Kimi-K2 公开代码和权重，并采用 Modified MIT License。它们显著降低了本地部署、适配与微调门槛，但不代表外部拥有完整训练数据、训练管线、算力配置和所有实验细节。

按 OSI 的 Open Source AI Definition，开放模型/开放权重还应具备用于推导参数的数据来源信息和代码。这个标准说明：**能下载权重，是重要开放，但不是完整开放的充分条件。**

### 3. 对企业，关键价值是控制权与适配权

选择开放权重模型，企业得到的并不仅是“更便宜”：

- 可在私有环境处理敏感数据；
- 可针对领域语言、流程和工具做适配；
- 可避免单一 API 供应商锁定；
- 可由多家云与硬件服务商承接部署。

代价同样真实：部署、推理优化、运维、模型安全、许可证合规都要自己承担。对于多数团队，“权重可得”不等于“部署容易”。

### 4. 对投资和创业，应该看开放策略改变了哪一层价值

不要只问“它开不开源”，而应问：

1. 开放的是权重、代码、数据来源信息，还是只有 API？
2. 许可证是否允许商用、微调、再分发和衍生模型？
3. 这会降低谁的成本、抬高谁的竞争门槛？
4. 公司靠什么保留价值：托管服务、推理效率、数据飞轮、分发、行业工作流，还是下一代闭源能力？
5. 开放是否让其成为某个硬件、框架或开发者生态的默认选择？

## 可复用判断

**“开放”不是一个营销名词，而是一组可验证的资产、权限与限制。**

权重开放更像是把“可运行、可部署、可适配”的能力交给生态；完全开源才更接近把“可研究、可修改、可重建”的能力交给生态。两者都可能有商业价值，但对应的护城河、合规边界与投资含义不同。
